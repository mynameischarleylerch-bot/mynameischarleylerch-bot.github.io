feat(angler): the Upgrades panel -- 22 permanent perks, bought with rod coins

The button, the panel, renderUpgrades() and the purchase path, wired the same way as
every other panel here. Every row quotes buyUpgrade() BEFORE the click rather than
hard-coding a price check, so the gate the player is shown and the gate enforced on
the click are literally the same gate, and a row can never offer a Buy button for
something the rule would then refuse. A locked row says WHY -- a disabled button on
its own reads as a bug, and a locked upgrade is the row the player most wants to
read, so it is dashed rather than dimmed to the .55 used elsewhere in this page.

Buying repaints the bag badge and the dock as well as the panel, because one upgrade
can change the bag's capacity or the number of seals that fit. Not repainting them
leaves the HUD lying until the next reload.

The plan's draft of renderUpgrades() declared a local `const state = document.createElement`
for the gate line, which shadows the controller's `state` and would have broken the
click handler written three lines below it. Written as `why` instead.

Two of my own mistakes, both found the hard way:

- My new look-guard passed against a source file that was still carrying a live
  mutation from a timed-out probe run. The suite was green while the slot line was
  stuck on `1 > 1`, forever saying "one seal". A mutation run that is interrupted
  leaves the repo mutated, and the only way to know is to check the pattern rather
  than trust the count -- 677 tests passing proved nothing about that line. A test for
  the slot line now exists.
- An unreferenced vendor/fru-angler/media/aero-lake.jpg appeared mid-session, untracked
  and referenced by no code in a game that uses zero images, and it failed a
  deliberate file-hygiene test. Moved out to the scratch directory rather than deleted,
  so nothing the user might want is destroyed. It is at
  scratch/unplaced-angler-media/aero-lake.jpg if it was wanted.

Also fixed: the tests' import of fishing.js is multiline with a trailing comma and a
?v= stamp, so three attempts to add names to it with a single-line pattern matched
nothing and reported success anyway.
